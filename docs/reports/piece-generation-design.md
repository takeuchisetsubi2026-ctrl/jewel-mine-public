# vNextピース生成の設計・再現手順

基準はPR #1の8b598c808cdf3e17a7952575965129bee22b7033（4dfb818を含む）。

## 形状と保存互換性

既存ID 0〜32を変更せず、ID 33に2×3を追加。既存ID 12が3×2、5が2×2、13が3×3、9/23が横/縦4棒、24/25が横/縦5棒。
現在の抽選除外は27/29。c188170以前を含む履歴と現行PIECE_POOL、旧セーブ移行に除外指定を確認した。別の予備形状の削除要求は履歴から確定できないため、その他の既存形状は推測で削除していない。専用の小型救済セットfallbackは廃止し、既存の「その他」分類の形状だけを条件付き抽選で使う。

保存キーjewel-mine-v35と既存フィールドは維持。sessionBestを追加する。新ゲームで保存済みbestを固定し、再起動時も維持。旧セーブは読み込み時のbestを一度だけ補完する（当時の開始時bestは復元不能）。best=0の場合は設定firstBest=10000を難易度判定の分母として使用。既に提示された3ピースは交換しない。

## 基礎抽選と盤面補正

index.htmlのcreatePieceGenerator内configが設定元。基礎分類重みは指示値。棒は長さ4/5がconfig.bar4Share=.5、縦横50:50。長方形2方向も等確率。

通常候補8、9+9+6候補1、四角+長方形+棒候補1、合法な3手を組む候補2（最大12候補）。構築候補は現在の仮盤面で置ける形状に条件付けて基礎重みを再正規化し、配置・実ライン消去を3回進める。既存の除外形状は使わない。

各候補は全6配置順序を対象に探索。各段階で全合法配置を調べ、同じ盤面・全消し履歴の重複を除き、上位8状態へ絞る。32bit×2の占有モデルで縦横完成ラインを同時判定し、その和集合を消す。構築候補の手順も独立に再生して合法性を確かめる。

配置順序6通りは評価するが、全座標の組み合わせを無制限に完全探索する実装ではない。探索で見つかった成功のみをcomplete/allClearとする。exhaustive=falseの未発見は「不可能」ではない。exhaustiveを付け、具体的なpathを検証に使う。

全配置の証跡がある候補が存在すればその中から選ぶ。評価は消去数、同時複数消去、棒の消去、全消し、四角形と棒の組み合わせ、順序の柔軟さ、初期盤面で置けない大型を考慮。softmax（温度28/48）で選ぶので、常に最高評価だけを提示しない。ユーザーが探索と異なる順で置けば失敗することはある。配置先の強制や自動盤面消去はしない。

基礎比率と最終提示比率は同一ではない。後者は候補の追加・合法性の条件付け・評価選択・初期盤面・プレイヤー方針に依存する。piece-base-statistics.jsonとpiece-simulation.jsonへ分けて記録する。

## 再現

```bash
npm ci
CHROMIUM_PATH=/usr/bin/chromium npm test
npm run test:simulation
npm run sync:android
npm run check
```

CHROMIUM_PATHを省略したCIでは既存のChromeチャンネルを使う。基準方式の比較にはgit履歴8b598c8が必要。Actionsはfetch-depth: 0。

統計は両モード各100000個、固定シード20261025/20261026。シミュレーションは12シード（20261025 + i*97）、空盤面・20セル・36セルから開始。完成済み初期ラインを正規化。モード固定、宝石・FEVER・スコア進行なし、同じ1手先貪欲方針（消去、近いライン、大きさ、固定シードの同点解消）、最大200配置。各モード・方式36ゲーム。生存ゲームは右打ち切りで、寿命の正確な平均とは解釈しない。

raw gamesに配置数、初期条件、ライン、複数消去、全消し、棒消去、生成大型、残留大型を保持。summaryに分位点・補正後分類比率・生成時間を保存。

## 判断の限界

最終比較ではライン・複数消去・棒消去の指標は改善したが、平均配置数は短縮し大型残留率は増加した。長く遊べることや全モードで全消しが増えることは実証していない。新方式の処理時間も旧方式より増える。Androidの入力待ち・補充時停止・体感難易度は未検証なのでPRはドラフトとする。暫定比率・初回基準10000・探索幅・評価温度の妥当性は実機テストで判断する。
